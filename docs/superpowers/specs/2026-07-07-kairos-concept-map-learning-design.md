# Kairos 概念地图学习法设计

> **状态：已确认**  
> 设计日期：2026-07-07  
> 主题：通过建立以 Kairos 项目为中心的技术概念地图，解决"学新概念时不知道它是什么、属于哪一层"的问题。

---

## 1. 问题背景

用户在学习技术时遇到的真实链条：

```
看到新概念 → 不知道它是什么/属于哪一层 → 硬看 → 看完就忘 → 偶尔记得也是散的 → 遇到问题时描述不清、问不到点
```

根因：**新概念没有"位置"**。它不与已有知识连接，不与项目场景绑定，因此无法被分类、记忆和调用。

## 2. 目标

建立一套以 **Kairos 项目** 为中心的"概念地图"学习法：

- 每个新概念必须能找到在项目中的位置
- 每个位置上的概念必须能用统一格式解释清楚
- 通过持续填充地图，逐步形成完整的基础知识体系
- 最终能支撑面试中的项目讲解与技术问答

### 3.2 节点格式（完整版）

每个技术概念统一按以下 7 个字段填写：

```markdown
### Docker

- **一句话定义**：把应用和运行环境打包成"容器"，保证在不同机器上运行结果一致。
- **为什么存在**：解决"在我机器上能跑，到你机器上跑不了"的环境不一致问题。
- **Kairos 哪里用了**：
  - 每个 demo 后端都有 Dockerfile
  - `deploy/docker-compose.yml` 把多个容器一起启动
  - 生产服务器用 Docker 部署
- **和相邻概念的关系**：
  - 比虚拟机轻量
  - Docker Compose 是管理多个 Docker 容器的工具
  - 镜像 ≈ 类，容器 ≈ 实例
- **常见面试问法**：
  - "Docker 和虚拟机有什么区别？"
  - "Docker 镜像和容器的区别是什么？"
  - "你们项目为什么用 Docker？"
- **我踩过的坑 / 注意点**：
  - 容器 IP 变化后，Nginx 反向代理需要重启
  - 中国大陆拉 Docker Hub 镜像可能超时
- **推荐学习资源**：
  - Docker 官方 Get Started
  - 项目中的 `deploy/docker-compose.yml`
```

### 3.3 学习方法论（判断与深入）

遇到新概念时，按以下决策树处理：

```
1. 这个概念在 Kairos 里出现吗？
   ├── 是 → 放入地图对应层级
   └── 否 → 放入"待归档区"，等以后项目中遇到再迁移

2. 它是基础概念还是高级特性？
   ├── 基础概念 → 必须填完 7 个字段，能口头解释
   └── 高级特性 → 只填"一句话定义 + 为什么存在 + 相关概念"，不深究

3. 它影响项目运行吗？
   ├── 是 → 必须找到代码/配置中的实际使用位置
   └── 否 → 了解即可，不强求代码定位

4. 我现在能讲清楚吗？
   ├── 能 → 标记为 ✅
   └── 不能 → 24 小时内再复习一次，用费曼法讲给自己听
```

### 3.4 使用流程

1. **建骨架**：先完成 6 大层 + 子分类，不填充细节。
2. **逐个填**：每学一个新概念，按 7 字段格式补充。
3. **贴地图**：把新概念放到对应层级；如果放不进去，说明层级需要调整。
4. **定期回顾**：每周快速扫一遍地图，标记仍为空壳或模糊的概念。
5. **面试转化**：每月把地图中 ✅ 的概念转化为"项目经历话术"。

### 3.5 学习节奏建议

- **每天**：遇到新概念时，花 10 分钟填一个节点。
- **每周**：回顾一次地图，把模糊节点标红。
- **每月**：选 3-5 个已掌握概念，练习口头讲解。

## 5. 第一个里程碑

完成地图骨架 + 填充 **15 个核心节点**，并为每个节点写好 7 字段内容。

| 层级 | 核心节点 |
|---|---|
| 基础设施层 | Git、Docker、Docker Compose、Nginx |
| 后端服务层 | Python、FastAPI、Uvicorn、RAG、FC |
| 前端门户层 | React、Vite、TypeScript、TailwindCSS |
| AI / Agent 能力层 | LLM、Function Calling |
| 通用 | HTTP / REST API |

**示例节点**：设计 doc 中已包含 Docker 的完整 7 字段示例，作为模板。

## 6. 验收标准

- 骨架覆盖 Kairos 项目所有主要技术领域
- 15 个核心节点均能用 7 字段格式讲清楚
- 每个核心节点至少包含一个项目中的具体使用位置
- 每个核心节点至少包含一个常见面试问法
- 用户能独立为一个新概念找到地图位置并按格式填充

## 7. 后续扩展

- **面试版**：每个节点扩展"面试官追问链"和"标准回答模板"
- **坑点版**：加入更多实际踩坑记录
- **进阶版**：为每个概念添加"官方文档 + 推荐文章 + 最小可运行例子"
- **关联版**：在节点之间增加超链接，形成真正的知识网络

## 8. 设计升级说明

相比初版，本次 enriched 版本增加了：

1. **更细的层级**：6 大层下增加子分类，避免单一层级概念过载。
2. **更完整的节点格式**：从 4 字段扩展到 7 字段，加入关系、面试问法、坑点、资源。
3. **学习方法论**：增加"基础 vs 高级"判断树和"是否影响运行"判断标准。
4. **示例节点**：给出 Docker 完整示例，降低填写门槛。
5. **面试衔接**：每个节点包含常见面试问法，为后续"面试表达"子项目预留接口。
